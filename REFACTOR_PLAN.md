# MultiPulti Refactor Plan

Дата аудита: 8 октября 2026 года. План составлен по актуальному рабочему дереву, а не только по README. Production-код, зависимости и существующие тесты не изменялись.

## Current architecture

MultiPulti — клиентское React-приложение с одним экраном, Canvas 800×600 и двумя слоями: основной canvas содержит растровый кадр, overlay — незавершённый штрих, фигуру, текст, стикер или выделение. DOM input используется для ввода текста. Шаблоны для обводки — отдельные DOM-изображения, не часть рисунка.

- `src/App.tsx`: **1296 строк**. Здесь остаются состояние инструментов, временные объекты, pointer-обработчики, рисование, финализация, трансформации выделения, операции таймлайна, импорт, запуск экспорта, сопоставление текста и координация компонентов. Вынос панелей в компоненты уже выполнен; называть App исключительно тонким координатором пока неточно.
- `src/types/editor.ts`: кадр представлен строкой PNG/dataURL; `FrameHistoryEntry = { frames: string[] }`. У кадров и временных объектов нет связи через устойчивый frame ID. `ActiveSelection` хранит mutable `HTMLCanvasElement`.
- `src/hooks/useFrameHistory.ts`: snapshots всего списка кадров, индекс истории и отдельно индекс текущего кадра. При сохранении redo-ветка обрезается. Для новых сохранений установлен предел 50 записей.
- `src/hooks/useProjectPersistence.ts` + `src/services/projectStorage.ts`: синхронная сериализация всей истории в `localStorage` при изменении истории, её индекса, текущего кадра или палитры. Есть базовая валидация загрузки и fallback до одной записи истории.
- `src/hooks/useAnimationPlayback.ts`: `setInterval` переключает тот же `currentFrame`, который используется редактированием и persistence.
- `src/hooks/useContentModeration.ts`: после некоторых растровых действий анализирует основной canvas и при блокировке удаляет/очищает кадр, сбрасывая историю. Есть двухсекундный cooldown.
- `src/hooks/useKeyboardShortcuts.ts`: один listener с актуальными callback через ref; ввод в input/textarea/select/contenteditable исключён.
- `src/components/*`: интерфейс и передача событий. `ToolSettingsPanel` дополнительно угадывает связь растрового выделения с текстом по пересечению прямоугольников.
- `src/canvas/operations.ts`: геометрия координат, штрихов и фигур, hit testing. `src/utils/*`: растровая заливка, извлечение связного компонента/области, эвристики формы/содержимого, GIF, звук, CSS-классы.
- `src/services/imageExport.ts`: скачивание PNG и ленивый импорт GIF-кодировщика. GIF формируется последовательно на главном потоке.

## Confirmed problems

Severity: **Critical** — потеря/подмена работы; **High** — неверный результат или разрушение важных инвариантов; **Medium** — заметные ограничения, расходы ресурсов или недоступность функций; **Low** — поддерживаемость/второстепенное улучшение. P0–P3 задают порядок работ, а не заменяют severity.

### C01. Выделение записывает промежуточный кадр без объекта

- **Модуль:** `src/utils/extractObject.ts`, `src/App.tsx:459`, `src/App.tsx:811`, `src/App.tsx:250`.
- **Причина:** обе функции extraction копируют выбранные пиксели в новый canvas, заменяют их на непрозрачный белый и вызывают `ctx.putImageData`. App сразу вызывает `saveCanvasSnapshot`; временное выделение в историю не входит. `pointerup` при перемещении только сбрасывает флаг; финализация происходит позже, например при смене инструмента.
- **Доказательная цепочка:** `H0 = объект в исходной позиции` → extract → `H1 = bitmap без объекта` → overlay с перемещённым объектом → finalize → `H2 = bitmap с объектом в новой позиции`. Undo из H2 возвращает H1. Если объект был единственным рисунком, кадр станет визуально пустым. Второй Undo возвращает H0.
- **Пользовательский эффект:** Undo перемещения скрывает объект вместо возвращения позиции. Reload после выделения восстанавливает H1 и теряет overlay; PNG/GIF в этот момент также не содержит объект. Undo при незавершённом выделении может восстановить bitmap, сохранив overlay, а последующая финализация — создать дубликат.
- **Severity / приоритет:** Critical / P0.
- **Решение:** оформить выделение как транзакцию с исходным состоянием и владельцем-кадром. Извлечение и preview не должны изменять committed history. Commit движения/трансформации/удаления — одно состояние; cancel полностью восстанавливает исходное. Не ограничиваться удалением одного вызова snapshot: тогда canvas, persistence и экспорт всё ещё смогут расходиться с pending state.

### C02. Временные объекты не принадлежат кадру и переживают смену контекста

- **Модуль:** `src/App.tsx:77`, `src/App.tsx:101`, финализаторы `194–269`, операции кадров `1001–1034`, `src/App.tsx:1240`; типы `ActiveSelection`, `ActiveText`, `ActiveSticker`.
- **Причина:** pending state глобален для App и не содержит frame ID. Выбор кадра вызывает только `setCurrentFrame`; add/copy/delete/reorder, Undo/Redo, clear, import и playback не имеют общего перехода, который завершает/отменяет pending. Финализаторы рисуют на текущем основном canvas и используют snapshot callback текущего кадра.
- **Сценарий:** кадр 1 → извлечь объект/начать текст/создать стикер → выбрать кадр 2 → дождаться его загрузки → сменить инструмент либо нажать ОК/Enter. Объект записывается в кадр 2. Для extraction кадр 1 уже сохранён без выбранных пикселей.
- **Другие эффекты:** clear не отменяет выделение/текст/стикер, поэтому объект можно снова «приклеить» к очищенному кадру. Copy копирует committed bitmap без pending. Playback оставляет временные объекты поверх меняющихся кадров; финализация текста и стикера остаётся доступной через input/панели и смену инструмента. `select` сохраняет activeSticker, но его overlay очищает и отдельного перемещения стикера в select нет.
- **Severity / приоритет:** Critical / P0.
- **Решение:** один pending session с `ownerFrameId`, `before`, видом действия и preview. Все смены frame/history/project и запуск playback проходят через единый resolver; нормальная навигация сначала commit в исходный кадр, cancel — явное действие. Clear/delete целевого кадра имеют определённую политику отмены pending. До загрузки destination canvas нельзя допускать commit. Playback должен быть режимом просмотра без финализации/импорта/очистки.

### C03. Undo/Redo не восстанавливает валидный текущий кадр

- **Модуль:** `src/hooks/useFrameHistory.ts:8–27`, `src/App.tsx:179–190`, `src/App.tsx:1135`.
- **Причина:** history содержит только frames. Undo/Redo меняет `historyIndex`, но не нормализует `currentFrame`; при загрузке из storage clamp есть, при runtime переходах — нет.
- **Сценарий:** добавить второй кадр → он выбран → Undo добавления → один кадр, `currentFrame = 1`. Проверка hook с mock setters получила `frames[currentFrame] === undefined`.
- **Эффект:** renderer показывает fallback blank, PNG получает undefined, copy может вставить undefined, рисование может снова расширить массив. При откате нескольких кадров возможны holes, которые JSON превращает в null, а storage validation затем отвергает такую запись. Undo reorder также оставляет выбранным индекс, который может относиться уже к другому кадру.
- **Severity / приоритет:** High / P0.
- **Решение:** атомарный переход документа и выбора. В текущей модели немедленно clamp на каждом переходе истории; в целевой — selection по frame ID и явно заданная политика при исчезновении кадра. Сохранение/экспорт должны требовать существующий кадр, а не молча подставлять пустой.

### C04. Асинхронная загрузка может перезаписать более новое состояние

- **Модуль:** `src/App.tsx:330–342`, `src/App.tsx:1058–1082`.
- **Причина:** эффекты `new Image` не имеют cleanup, generation token или проверки актуальности в `onload`; нет `onerror`. Импорт захватывает старые `frames`, `currentFrame`, `saveState`, но пишет на общий canvas, который к окончанию чтения может показывать другой кадр.
- **Эффект:** при быстрой навигации старый image callback может отрисовать чужой кадр. Импорт → новое рисование/Undo/перестановка/другой импорт → поздний callback способен восстановить устаревший список frames/history, стерев новые изменения. Проверка `isDrawingRef` стоит лишь перед созданием Image и не защищает его последующий callback.
- **Severity / приоритет:** Critical / P0. Наличие гонки доказано по callback; её частота зависит от времени декодирования.
- **Решение:** единый loader с reject/error и проверкой request ID. При импорте фиксировать frame ID; после decode применять к актуальному документу через атомарную операцию и проверять, существует ли цель. Нужна политика отмены устаревшего импорта и видимый статус. Canvas render не должен коммитить данные и не должен принимать устаревшие результаты.

### C05. `placedTexts` — глобальная и несогласованная с bitmap таблица

- **Модуль:** `src/App.tsx:106`, `src/App.tsx:212–248`, `src/App.tsx:310–327`, `src/App.tsx:1029`; `src/components/ToolSettingsPanel.tsx:40–50`; `src/types/editor.ts`.
- **Причина:** metadata текста существует только в памяти App. Нет frame ID, history synchronization и persistence. Matching использует >=30% пересечения с прямоугольником глобального текста, без связи с реально извлечёнными пикселями. После движения/scale/flip/tint растрового текста metadata не обновляется; clear одного кадра удаляет metadata всех кадров.
- **Эффект:** объект на кадре 2 в координатах текста кадра 1 может получить «Изменить текст» и чужую строку. Undo/delete/import оставляют устаревшие записи; copy не создаёт независимую текстовую сущность. После reload видимые буквы остаются в PNG, но исходная строка/шрифт/цвет исчезают и нормальное редактирование текста недоступно. Несвязанные буквы могут извлекаться по одной; conversion заменяет извлечённые пиксели всей строкой, оставляя другие буквы bitmap.
- **Дополнительно:** исходный размер не хранится как отдельное поле — `h` принимается за размер; при conversion размер выводится из selection.height и ограничивается 30–120. Панель textarea допускает переносы, а renderer использует один `fillText`, DOM input однострочный.
- **Severity / приоритет:** High / P1; межкадровую ошибку необходимо локально оградить уже в P0.
- **Решение:** текст как объект конкретного кадра с ID, строкой, размером, шрифтом, цветом и transform, входящий в history и persistence. До миграции минимальная metadata должна быть привязана к кадру и инвалидироваться вместе с bitmap. Не пытаться восстановить исходные строки из старых PNG эвристикой/OCR. Для следующей версии либо явно оставить однострочный текст, либо реализовать общую multiline layout.

### C06. Модель кадра теряет смысл объектов при каждом commit

- **Модуль:** `src/types/editor.ts:24–35`, `src/hooks/useFrameHistory.ts:23–27`, финализаторы App, `src/canvas/operations.ts`.
- **Причина:** committed frame — единственный PNG. Текст, emoji и фигуры растрируются; тип/параметры/порядок отдельных объектов не сохраняются. Выбор «объекта» означает пиксельную сегментацию, а не выбор сущности.
- **Эффект:** редактирование текста, геометрии и стикера ненадёжно; пересекающиеся рисунки сливаются, раздельные штрихи/буквы распадаются. Нельзя корректно изменить радиус круга, строку, emoji или стиль после reload.
- **Severity / приоритет:** High / P1, ограничение архитектуры, а не требование сделать полноценный векторный редактор.
- **Решение:** гибридный кадр: растровая основа и маленький упорядоченный список редактируемых text/sticker/shape объектов. Кисть, заливка, старые изображения остаются bitmap. Растровое выделение остаётся полезным инструментом для рисунка. Определить flatten/compositing для заливки/ластика/перекрытий до реализации объектов.

### C07. История хранит лишние состояния и допускает перезапись commits

- **Модуль:** `src/hooks/useFrameHistory.ts:15–27`, `src/hooks/useKeyboardShortcuts.ts`, `src/App.tsx:443–471`, `src/App.tsx:580–582`, `src/App.tsx:839–888`.
- **Причина:** `saveFrames` без проверки изменений всегда push; snapshot зависит от render closures `history`, `historyIndex`, `frames`. Два вызова до следующего render строят историю от одинаковой базы; поздний setter заменяет первый. Реальный путь — finalize прежнего selection/text и extract нового в одном pointerdown.
- **Эффект:** no-op fill/clear, клик фигурой без preview, выделение и возврат без движения тратят историю и сериализацию. Два логических действия в одном обработчике не получают независимых undo шагов. Предел 50 быстрее вытесняет полезные действия.
- **Отдельная ошибка shortcuts:** если redo недоступен, Ctrl+Shift+Z проходит дальше в ветку `key === "z" && canUndo` и выполняет Undo. Нужно распознавать комбинацию независимо от доступности команды; недоступный Redo не должен превращаться в Undo.
- **Severity / приоритет:** High / P1.
- **Решение:** один reducer для document/history/navigation, atomic command/transaction. Одна пользовательская завершённая операция — одна запись; selection и pointermove не являются commits. Проверять изменение revision/patch, не stringify всего проекта для dedup. Ограничить историю и по числу операций, и по байтовому бюджету. Проверять serial commits и branching в настоящем React integration test.

### C08. Дорогая сериализация, тихий отказ сохранения и потеря истории при quota fallback

- **Модуль:** `src/hooks/useProjectPersistence.ts`, `src/services/projectStorage.ts:37–51`, playback hook.
- **Причина:** каждый effect синхронно делает `JSON.stringify(state)` и `localStorage.setItem`. История сериализует повторные dataURL каждого кадра в каждой записи; debounce/dirty project revision нет. При ошибке сохраняется одна запись текущего проекта; при повторной ошибке остаётся только console.error, API не сообщает результат UI.
- **Эффект:** паузы после действий, при изменении палитры и даже каждом playback tick (2/5/12 раз в секунду). После успешного fallback reload лишается undo-истории; если fallback также не поместился, новые изменения не сохранены и пользователь об этом не знает. При наличии прежнего storage оно остаётся устаревшим. При отсутствии записи reload начинает пустой проект.
- **Severity / приоритет:** High / P2; видимый статус ошибки сохранения и прекращение сохранений на playback — ранняя P0 защита.
- **Решение:** versioned storage adapter с результатом/status, coalesced dirty saves, отдельное сохранение document и preferences. IndexedDB оправдан для этого проекта: асинхронные transactions, Blob вместо base64, общий asset storage и меньшая цена роста числа кадров. Историю держать ограниченной в памяти; сохранять её ограниченный хвост только если это осознанное продуктовое требование. Не полагаться на unload для единственного сохранения.

#### Оценка памяти и объёма: важные различия

Один RGBA buffer 800×600 = 1 920 000 байт (~1.83 MiB). Основной canvas и overlay имеют по backing store, extraction создаёт ещё ImageData, маску/stack/objectPixels и canvas выделения. Browser/GPU/decode caches могут добавить память; здесь они не измерялись.

PNG сжат, base64 увеличивает размер бинарного PNG примерно на 1/3. Но **snapshots не означают 50 полных копий всех растров в JS RAM**: `[...frames]` копирует массив ссылок, неизменённые строки переиспользуются. RAM зависит от суммы уникальных версий изменённых кадров, строкового представления движка, decoded images и массивов ссылок.

Наоборот, `JSON.stringify` повторяет содержимое строк независимо от общей ссылки. Иллюстрация, не замер: 20 кадров × 50 history entries × 100 KiB символов dataURL ≈ 97.7 MiB JSON без малого overhead. Если меняется один кадр, в памяти до сериализации может быть около 20 + 49 уникальных строк (~6.7 MiB при однобайтном представлении, больше при другом представлении), но storage JSON остаётся примерно того же большого порядка. При загрузке нет гарантии такой же экономии строк.

Точная quota зависит от браузера/режима/окружения; число кадров само по себе её не предсказывает. Нужны измерения `serialized.length`, объёма Blob, `storage.estimate` при наличии API и heap/long tasks в браузере. Даже 50 записей не являются байтовым лимитом. Loader также принимает историю любой длины; один `shift` при сохранении не уменьшит загруженную историю >50 сразу до 50.

### C09. Валидация сохранённого проекта неполная

- **Модуль:** `src/services/projectStorage.ts:5–34`.
- **Причина:** frames проверяются только как непустой массив строк; формат/декодирование изображений, версия схемы, размер документа и пределы истории не проверяются. `JSON.parse` большой истории синхронен. Ошибки загрузки возвращают null без recovery UI; автосохранение нового blank проекта может заменить некорректную исходную запись.
- **Эффект:** строка `not an image` проходит проверку; renderer остаётся с прежним изображением или пустым canvas, GIF может зависнуть. Повреждённое хранилище не объясняется пользователю и не сохраняется для восстановления.
- **Severity / приоритет:** High / P2; недеструктивный recovery — P0 для загрузки повреждённых данных.
- **Решение:** schema version, ограничения размера/количества, проверка decode на границе миграции/загрузки, явный recovery state и сохранение исходных данных до подтверждённой успешной миграции. Не выполнять молчаливое автосохранение пустого проекта поверх failed load.

### C10. Pointer lifecycle не изолирован и cancel оставляет несовпадающее состояние

- **Модуль:** `src/App.tsx:418–903`, `src/components/DrawingStage.tsx:30–41`.
- **Причина:** capture есть, но единого active pointer ID нет; второй touch/pen/mouse меняет общие refs и может закончить чужой жест. Нет `lostpointercapture`. `pointercancel` сбрасывает drawing/selection/text refs, но не sticker move/resize refs. Ластик изменяет основной canvas во время move, cancel не rollback и не snapshot. Up сразу выходит при `isPlaying`, не завершая lifecycle.
- **Эффект:** multi-touch смешивает начальную позицию/штрих. После отмены стирания bitmap отличается от frames/history/persistence: следующий snapshot может неожиданно сохранить отменённое стирание, reload/экспорт его не отражает. Cancel стикера может оставить resize/move флаг; последующие движения указателя продолжают трансформацию. Capture, потерянный без cancel/up, не имеет общего завершения.
- **Координаты:** преобразование client→canvas через rect и отдельные X/Y масштабы корректно для обычного CSS resize. Координаты captured pointer могут выходить за холст; рисование клипуется Canvas, rect extraction и floodFill имеют bounds. Политики перемещения объекта за край/полностью вне кадра нет; finalize обрежет/потеряет его видимую часть. Pressure, tilt, coalesced events не используются — это ограничение качества stylus, не отсутствие поддержки pen.
- **Severity / приоритет:** High / P0 для lifecycle/cancel; стилизация pen и политика края — P3.
- **Решение:** хранить active pointer ID, принимать один разрешённый primary жест, единый end/cancel/lostCapture с определённым rollback/commit. Проверять button и owner pointer. Ластик также выполнять как транзакцию. Bounds применять по операции: не зажимать все stroke coordinates, иначе появятся линии вдоль края. Вынос в `useCanvasInteraction` имеет смысл после фиксации контрактов.

### C11. Extraction — разрушительный пиксельный алгоритм с ограниченным пониманием фона

- **Модуль:** `src/utils/extractObject.ts`, `src/canvas/operations.ts:isSelectionPixelAt`.
- **Причина:** фон = прозрачный либо RGB >250; connected selection использует 8 соседей и игнорирует цвет/семантику. Rect selection вырезает все небелые пиксели области. Вырезанные пиксели заменяются белым, а не восстановленным нижним слоем. Даже rect сначала читает весь canvas. Stack и objectPixels — динамические JS-массивы, плюс полный RGBA и visited.
- **Эффект:** на фото/цветном фоне выделяется крупный связный участок вплоть до всего изображения, остаются белые отверстия; белые части emoji/фигуры становятся прозрачными и теряют форму на цветном фоне. Связанные штрихи сливаются, буквы без соединений разделяются. Большие области создают заметную временную память и работу главного потока.
- **Severity / приоритет:** Medium / P1 для контракта, P3 для оптимизации; разрушительное взаимодействие с history отдельно описано в C01.
- **Решение:** разделить вычисление mask/bounds/bitmap и применение операции. Сначала определить white-paper raster semantics и поведение цветного/прозрачного фона. Для объектов использовать semantic hit testing, для растровых выделений — mask плюс transaction. Rect может читать только ограниченную область; typed queues/переиспользование buffers рассматривать после профилирования. Не обещать восстановление скрытых пикселей в старом flattened PNG.

### C12. Модерация разрушает обычные рисунки и не покрывает все пути

- **Модуль:** `src/utils/contentFilter.ts:55–85`, `src/utils/contentFilter.ts:324–383`, `src/hooks/useContentModeration.ts`, `src/hooks/useFrameHistory.ts:29–41`, вызовы `checkCanvasContent` в App.
- **Причина:** threshold severity >=60; палитра может дать 80 без формы, диагональный cross даёт 70 сам по себе. Комментарий о необходимости комбинации признаков расходится с фактической формулой. На block сбрасывается вся история и удаляется текущий кадр либо заменяется единственный кадр blank.
- **Проверено исполнением:** два несоприкасающихся квадрата 20×20, один чёрный и один красный, дают block severity=80; большой синий X под 45° — block severity=70. Это конкретные false positives, а не только гипотеза.
- **Где запускается:** завершение кисти и фигур, заливка. Не запускается при импорте, finalizeSelection, recolor/flip/scale с последующей финализацией, finalizeText/sticker, загрузке проекта и экспорте; ластик также не проверяется. Во время двухсекундного cooldown `checkCanvas` возвращает false вообще без анализа, то есть это окно пропуска проверки, а не только подавления уведомлений.
- **Эффект:** разрешённый детский рисунок может необратимо потерять кадр и undo всей работы. Нежелательные по критериям фильтра изображения можно импортировать/перекрасить/сохранить через непроверяемые маршруты. Эта система не проверяет смысл текста или изображения.
- **Стоимость:** один `getImageData` всего кадра (~1.83 MiB), несколько проходов пикселей, многократный поиск линий на уменьшенной сетке и попарное сравнение всех найденных линий O(L²). Даже залитая область может дать много дублирующихся линий. Производительность нельзя оценивать только ценой readback.
- **Severity / приоритет:** Critical / P0 для разрушительных false positives; покрытие и стоимость — P3 после решения о продуктовой политике.
- **Решение:** сначала заменить необратимое удаление на недеструктивный warning/review с сохранением рисунка. Если запрет обязателен, явно определить quarantine/recovery и правила history; не лечить это одним повышением threshold. Разделить analyze и notification cooldown, анализировать immutable candidate до commit согласно единой политике. Собирать reason/fixtures, проверять alpha также в pattern detectors (сейчас там учитывается RGB без alpha), уменьшать разрешение/число дублирующихся линий. Worker — только при подтверждённой необходимости. Сервер не требуется для рефакторинга.

### C13. Импорт деформирует изображения и не ограничивает ресурсы

- **Модуль:** `src/App.tsx:1058–1082`, `src/components/HeaderToolbar.tsx`.
- **Причина:** `accept="image/*"` — только подсказка picker; нет проверки file.size/MIME/decode dimensions. FileReader создаёт base64, Image декодирует исходник полного размера. `drawImage(img, 0, 0, 800, 600)` без сохранения aspect ratio; сначала canvas очищается до прозрачного. Reader/Image не имеют error/abort handlers.
- **Эффект:** квадратное/портретное фото растягивается; очень большой файл может занять много памяти и задержать UI до уменьшения до 800×600. Невалидный файл не объясняется пользователю. Прозрачный PNG визуально лежит на белом DOM фоне, но экспорт PNG сохраняет прозрачность, GIF принудительно добавляет белый фон — результаты различаются.
- **Severity / приоритет:** High / P0 для ошибки/гонки, Medium / P3 для качества/ресурсов.
- **Решение:** decode boundary с проверками bytes/dimensions/type и явной ошибкой; contain/cover с сохранением пропорций и определённый white/transparent фон. Object URL/decode/downsampling могут снизить лишнее base64, но не отменяют проверки decoded размера. Последующие async callbacks должны соблюдать C04. Не заменять существующий рисунок до успешного decode.

### C14. Экспорт не учитывает pending, GIF способен зависнуть и блокировать UI

- **Модуль:** `src/App.tsx:1037–1056`, `src/services/imageExport.ts`, `src/utils/gifExport.ts`.
- **Причина:** PNG использует сохранённый `frames[currentFrame]`, GIF — массив frames без overlay. В GIF Promise назначен только `img.onload`, нет reject по error; canvas context используется с non-null assertion. `quantize`, `applyPalette`, `writeFrame`, `finish` выполняются синхронно на main thread, хотя обёртка async.
- **Эффект:** незавершённый текст/стикер не попадает в экспорт, extraction экспортирует дырку. Один повреждённый dataURL оставляет экспорт pending навсегда и `isExporting=true`; проверено с mock Image error. На длинной анимации UI задерживается; прогресс/отмена отсутствуют. Воспроизведение тоже декодирует new Image на каждом tick без cache/дедупликации и проверки порядка загрузок.
- **Severity / приоритет:** High / P0 для корректного результата/зависания, Medium / P3 для responsiveness.
- **Решение:** сначала получить консистентный immutable export document через pending resolver или renderer preview без декоративных рамок; reject decode errors и всегда снимать busy через finally. Проверять размеры/FPS/контекст, выдавать понятную ошибку кадра. GIF с frame-local palette оставляет возможность цветового мерцания — оценить визуально, не считать уже доказанным дефектом. После profiling добавить progress/cancel, bounded decode cache для playback и worker encoding при необходимости.

### C15. Мобильная компоновка и DOM текст не соответствуют размеру холста

- **Модуль:** `src/components/DrawingStage.tsx:27–65`, `src/components/ToolsPanel.tsx:14`, `src/components/ToolSettingsPanel.tsx:53`, `src/components/Timeline.tsx`, `src/index.css:49–54`, оболочка App.
- **Причина:** несворачиваемые sidebar 72+192 px (<640) или 88+240 px (>=640), горизонтальная flex-компоновка, main padding 16/32 px с каждой стороны, header 64 px, timeline 160 px. Canvas ограничен шириной/aspect ratio, но не вычисляется fit по доступной высоте. Root использует h-screen, body/main overflow hidden. Body `touch-action:none` распространяет запрет touch-pan и на прокручиваемые панели/таймлайн. FPS controls скрыты ниже sm без альтернативы.
- **Эффект по геометрии кода:** на 320 px после sidebar остаётся всего 56 px для main ещё до padding; на 375 px —111 px. Canvas чрезвычайно мал или переполняется минимальным содержимым. В низком landscape высота сцены может обрезаться. Native touch scrolling конфликтует с запретом pan; обычного touch reorder и keyboard reorder нет (только HTML draggable).
- **Текст:** position в процентах привязан к canvas логично, но fontSize = `size / 600 * 100vh` зависит от высоты viewport; width — unscaled px, `text.length * size * 0.6`, без font metrics. Для отображаемой высоты canvas D правильный font size порядка `size * D / 600`, а не `size * viewportHeight / 600`. Поэтому размер при вводе и после fillText различается; input может выйти за canvas и обрезаться overflow. `document.fonts` не ожидается, Google Fonts могут ещё не загрузиться или быть недоступны; metadata metrics и raster appearance могут различаться во времени.
- **Severity / приоритет:** High / P3 для доступности редактора на телефоне, Medium для точности ввода. Точные screenshot/device эффекты требуют браузерного QA.
- **Решение:** collapsed tools/settings drawer либо bottom sheet на малых экранах; fit canvas по двум доступным размерам, dynamic viewport/virtual keyboard; общая canvas→DOM transform с ResizeObserver и font metrics, общий font weight/layout. Touch-action:none только на drawing surfaces, разрешённый pan на panels/timeline; mobile FPS и простые reorder кнопки. Проверить portrait, landscape и клавиатуру до принятия нового layout.

### C16. Доступность ключевых операций и покрытие тестами недостаточны

- **Модуль:** `src/components/Timeline.tsx`, `src/components/EditorModals.tsx`, `src/components/ToolSettingsPanel.tsx`, `src/components/DrawingStage.tsx`, `scripts/test-content-filter.ts`, `package.json`, `tsconfig.json`.
- **Причина:** кадры — clickable div без keyboard semantics; context menu вызывается правой кнопкой без явной touch/keyboard альтернативы удаления selection. Modals без dialog/aria-modal, focus trap/restore и Escape. Часть swatches/icon buttons/inputs не имеет доступного имени; title есть не везде и не заменяет все необходимые состояния. Нет aria-pressed для инструментов/переключателей, live save/error status. Текст input не учитывает IME composition перед Enter. Canvas не описан доступным текстом.
- **Эффект:** keyboard/screen reader и touch пользователи не получают все операции; focus может оставаться за модальным окном, подтверждение IME может преждевременно завершить ввод. Эти пути не защищены текущими тестами.
- **Тесты по факту:** единственный script содержит safe blue patch, blocked black/red cross и mock anchor download. Он не проверяет React, реальный Canvas, history, persistence errors, gestures, import, pending или GIF; успешный тест не доказывает их корректность. `strict` выключен, build не запускает typecheck автоматически.
- **Severity / приоритет:** Medium / P3; characterization tests критических P0 путей нужны до изменения поведения.
- **Решение:** семантические buttons и доступные имена/states, focus management, явные delete/commit/cancel и reorder controls, labeled inputs и statuses. Усиливать TypeScript постепенно по затронутым модулям; не начинать рефакторинг с массового strict fix. Тестовый набор описан ниже.

### C17. App объединяет доменные переходы и изменяемый Canvas; есть второстепенные расходы

- **Модуль:** `src/App.tsx`, `src/canvas/operations.ts:drawSmoothedCurve`, `src/utils/floodFill.ts`, ассеты, Git tree.
- **Причина:** history, mutable canvas и pending обновляются разными путями. Каждый pointermove кисти заново отрисовывает все накопленные точки, суммарно O(n²) по длине штриха; moving selection/text/sticker вызывает React state update и перерисовку панелей. FloodFill делает несколько полных проходов, typed masks/queue и обходы окрестностей; стоимость на main thread ощутима потенциально, но не измерена.
- **Эффект:** большая поверхность изменений и риск рассинхронизации; на длинных штрихах/мобильных устройствах возможны задержки. Начальный импорт логотипа 1.44 MB тяжёл для отображения 48×48. В Git уже отслеживаются 6768 файлов `node_modules` и `.vs` несмотря на `.gitignore`; это усложняет воспроизводимость и диффы. Существующие изменения `.vs` были до аудита и не затрагивались.
- **Severity / приоритет:** Medium / P2 для разделения ответственности; Low–Medium / P3 для optimizations/tooling.
- **Решение:** вынести только связные зоны с устойчивыми контрактами (см. Target architecture). rAF batching/preview refs и алгоритм incremental stroke вводить после замера и pixel regression tests, не отключать smoothing вслепую. Оценить стоимость flood fill и extraction отдельно. Ассеты/Git cleanup — отдельное низкоприоритетное изменение; сейчас ничего не удалять и не переустанавливать.

## Rejected assumptions

1. **«Branching после Undo всегда сломан».** Нет: `history.slice(0, historyIndex + 1)` корректно отбрасывает redo. Mock-проверка A→B→C→Undo→D дала A,B,D. Ошибка последовательных commits из одного render — другой механизм.
2. **«История бесконечно растёт при обычной работе».** Нет: новые штатные записи ограничиваются 50. Нет byte budget, dedup и ограничения большой загруженной истории; количество кадров также не ограничено.
3. **«Каждый snapshot делает deep copy всех PNG в RAM».** Нет: массивы копируются поверхностно. Основная повторная цена полного проекта возникает при сериализации, хранении JSON и потенциально при decode/load.
4. **«Quota fallback выбрасывает все кадры кроме активного».** Нет: сохраняется `history[state.historyIndex]` со всем массивом frames. Теряется история, не вся анимация. Текст console.warn/README «только текущий кадр» неточен. Предел quota всё равно может превысить и этот вариант.
5. **«localStorage вообще без catch/валидации».** Нет: оба сохранения и загрузка обработаны, indices clamp при загрузке есть. Недостатки — тихий результат, отсутствие version/decode validation/recovery и дорогая синхронная работа.
6. **«pointercancel и capture отсутствуют; за краем canvas всегда теряется pointerup».** Нет: есть Pointer Events, capture down, release up/cancel, touch-none. Обычный одиночный захваченный drag продолжает получать события за пределами. Проблемы касаются ownership, lostcapture, политики cancel и переключения режимов.
7. **«Touch и stylus вообще не поддержаны».** Нет: общий Pointer Events путь принимает touch/pen/mouse. Pen pressure/tilt и multiple pointer policy не реализованы; это разные требования.
8. **«CSS scaling всегда даёт неправильные координаты».** Нет: `getBoundingClientRect` и ratio canvas/rect корректно переводят client coordinates при обычном resize. DOM input масштабируется другим способом — это подтверждённая отдельная ошибка.
9. **«Extraction всегда цепляет соседние несвязанные предметы через большой зазор».** Нет: алгоритм использует только 8-connected component; поиск рядом до 10 px выбирает seed, но не склеивает отдельные компоненты. Rect selection осознанно выбирает несколько компонентов. Соприкасающиеся области действительно объединяются.
10. **«Все dataURL обязательно имеют одинаковую непрозрачную основу».** Нет: blank белый, но import очищает canvas и сохраняет alpha. Политику alpha нужно унифицировать, а не считать её уже заданной.
11. **«Фильтр запускается при каждом pointermove или требует backend».** Нет: только отдельные commit пути; вычисление полностью локальное. Тем не менее покрытие неполно, алгоритмы тяжёлые и существуют разрушительные false positives.
12. **«Модерация штатно удаляет кадр из неактуальной redo-ветки».** Не подтверждено в текущих маршрутах: каждый вызов checkCanvasContent следует за saveCanvasSnapshot, который сначала срезает redo. `discardBlockedFrame` использует latest history, а не historyIndex — это хрупкий API для будущих независимых вызовов, но прямой isolated mock такого вызова не доказывает достижимый сейчас UI-баг.
13. **«GIF async уже работает вне главного потока» / «GIF encoder загружается сразу».** Первое неверно: encoding синхронен. Второе тоже неверно: сервис делает dynamic import; production build подтвердил отдельный GIF chunk. Object URL освобождается через finally, постоянная утечка этого URL не подтверждена. Немедленный revoke после link.click требует browser download QA, а не объявления доказанного сбоя.
14. **«Горячие клавиши всегда мешают вводу».** Нет: editable targets исключены и callbacks актуализируются через ref. Есть узкая ошибка: Ctrl+Shift+Z при отсутствии redo может провалиться в последнюю ветку обычного Undo, если Undo доступен. Её стоит зафиксировать отдельным regression test и исправить в P0/P1 без переписывания всего hook.
15. **«App всё ещё содержит разметку всех панелей».** Нет: UI уже вынесен. Дальше нужно извлекать транзакции/interaction/import и модель, а не механически дробить JSX или создавать generic manager на каждый state.
16. **«Тестов вообще нет / проект не собирается».** Нет: test script и typecheck проходят, production build успешен. Покрытие узкое; начальный sandbox EPERM не является дефектом проекта.

## Target architecture

Минимальная цель — локальный редактор с тем же набором инструментов, двумя Canvas слоями и простым таймлайном. React state/useReducer достаточно. Redux, Zustand, server/backend, CRDT, бесконечный canvas и полноценная scene graph не нужны.

### 1. Один committed документ

Небольшая versioned модель:

```ts
type FrameId = string;
type AssetId = string;

interface ProjectDocument {
  schemaVersion: 2;
  width: number;  // на первом этапе 800
  height: number; // на первом этапе 600
  frames: FrameDocument[];
}

interface FrameDocument {
  id: FrameId;
  rasterAssetId: AssetId;
  objects: EditorObject[]; // упорядоченные text | sticker | shape
}
```

У объекта нужны ID, transform и параметры своего вида: text/string/font/fontSize/weight/color; sticker/emoji/font renderer; shape/kind/geometry/stroke/width. Начать с текста, затем emoji и фигур. Не записывать DOM canvas в сериализуемую модель. Immutable asset IDs ссылаются на растровые версии, in-memory cache хранит только необходимые decoded ресурсы.

Исторические PNG импортируются как rasterAsset; objects пуст. Для них доступны обычные растровые операции, но текст/фигуры задним числом не восстанавливаются как редактируемые сущности.

### 2. Явные композиционные правила

По умолчанию raster paper внизу, objects сверху в порядке массива. Это минимальная модель с реальным ограничением: stroke/eraser/fill по raster не перекрывают верхние объекты автоматически. Если пользователь должен рисовать/стирать по ним, перед такой операцией выполнять определённый undoable flatten затронутого содержимого либо всего кадра. Операция объясняется UI кратко, когда теряется редактируемость текста. Не вводить неограниченное число слоёв ради сохранения любой старой последовательности.

Object preview и export используют один renderer. Object edit меняет модель, а не распознаёт буквы по PNG. White/transparent background, измерение текста, fonts readiness и clipping определены в этом renderer. Template remains tracing aid; не включать его в export без отдельной пользовательской функции.

### 3. Один pending transaction

`PendingEdit` — discriminated union, а не три независимых nullable state. Поля: ownerFrameId, исходная revision/состояние, тип действия, preview. Одновременно одна активная операция. Pointer refs и preview Canvas — runtime resources; committed doc и history не меняются до commit.

События switch frame/tool, undo/redo, clear/delete/import, playback и export проходят через согласованный resolver. Commit/cancel/delete имеет единый контракт. Долгое незавершённое редактирование при reload не должно уничтожать committed bitmap; optional draft recovery сохраняется отдельно и не выдаётся за committed history.

### 4. Простая, атомарная history

На переходном этапе сохранить snapshots документа, но использовать immutable ссылки на assets/objects и транзакционный reducer. Это легче проверить, чем сразу переписывать всё на pixel diffs.

Затем ограниченный undo log: frame list operations, before/after object или affected rasterAssetId. Один gesture/редактирование текста/перемещение = один commit. New action after Undo удаляет redo; отменённые/нетронутые previews не пишутся. Ограничение по операциям и asset bytes; ресурсы освобождаются только когда недостижимы из current doc, undo, redo и pending. Сложные tiled pixel deltas — только если замеры докажут, что immutable raster checkpoints недостаточны.

Выбор кадра — по ID, policy восстановления после Undo удаления/вставки документирована. CurrentFrameIndex — производная для UI. Playback имеет отдельный displayFrameId/index и не меняет edit selection/persisted document каждые 80–500 ms.

### 5. Границы модулей без лишних абстракций

- `editor reducer / useEditorState`: документ, история, выбранный frame ID, доменные commands. Предпочтения инструментов могут оставаться обычным state.
- `usePendingEdit`: transaction lifecycle и context transitions; может быть частью reducer, если отдельный hook ухудшит атомарность.
- `useCanvasInteraction`: pointer ownership, gesture refs, sampling, завершение/отмена; вызывает commands и renderer, не пишет localStorage.
- `canvas/renderer` + существующие `canvas/operations`: рисование документа/preview и coordinates/text layout. Extraction/fill — отдельные алгоритмы с явным mutation contract.
- `image loader / import service`: decode, limits, aspect ratio, latest request guard; hook нужен только для busy/error/отмены UI.
- `projectStorage adapter` + существующий persistence hook: versioned IDB document/assets, migration/recovery/status. Preferences маленькие и могут остаться в localStorage.
- Существующие playback, keyboard, moderation, export modules сохранить, уточнив контракты. GIF worker добавлять отдельным этапом, когда encoding latency этого требует.
- App связывает эти части и JSX. Не задавать искусственный предел строк: критерий — отсутствие в нём низкоуровневого raster mutation и разных обходных путей commit.

## Migration strategy

Каждый этап — небольшой reviewable change с собственной проверкой. Весь этот раздел — план будущей работы; текущий аудит ничего из него не реализует.

### Подготовка: защита фактического поведения

1. Зафиксировать fixtures и characterization tests из следующего раздела, особенно history/pending/import. Проверки известных багов должны демонстрировать провал текущего поведения; не закреплять исчезновение объектов как желаемое.
2. Снять baseline heap/serialized bytes/long tasks на простом рисунке, фото, 20 кадрах и длинном штрихе; проверить реальные mobile viewport. Сохранить экспортированные PNG/GIF для визуального сравнения.
3. Зафиксировать schema v1, приоритеты и policy pending commit/cancel, alpha и текстовых переносов до реализации.

### P0 — реальные ошибки и потеря данных, без смены всей модели

1. Убрать destructive moderation false positives из пути необратимого удаления: warning/recovery вместо безвозвратной потери; разделить cooldown анализа и уведомления.
2. Исправить инварианты navigation/history: валидный currentFrame после Undo/Redo, raw setters за общей границей переходов, корректный Ctrl+Shift+Z без redo.
3. Ввести transaction для extraction с исходным bitmap: нет committed snapshot дырки; одно завершённое действие, cancel/reload безопасны. Зафиксировать pending owner frame, finalize-before-switch и политику clear/delete. Огородить глобальные text matches по кадру до полноценной модели.
4. Унифицировать pointer ownership/cancel/lostCapture и запрет редактирования во время playback; устранить несохранённый cancel eraser.
5. Защитить Image callbacks request IDs/owner frame; добавить decode errors. Export должен брать согласованный кадр; GIF обязан reject и снимать busy при любой ошибке.
6. Добавить видимый статус сохранения/failed load; не перезаписывать повреждённый проект blank. Убрать повторные project saves на playback и частые полные saves из выбора палитры.

**Gate:** объект не исчезает/не переезжает между кадрами, new edits не теряются от позднего импорта, некорректный индекс недостижим, cancel и reload дают согласованное состояние, failures видимы пользователю. Старый PNG storage остаётся читаемым.

### P1 — модель документа и history

1. Устойчивые frame IDs и immutable документ в reducer; adapter сохраняет прежний растровый формат на границе, пока persistence не мигрирован.
2. Atomic history commits, no-op suppression и limits; before/after raster references вместо размножения dataURL при сериализации. Сначала snapshots ссылок, потом короткие frame/object commands при доказанной пользе.
3. Добавить per-frame text objects и единый text renderer/layout; убрать `placedTexts` matching. Затем sticker/shape objects. Каждый подэтап проверяет copy/delete/reorder/undo/reload через schema adapter.
4. Ввести определённый flatten/compositing для raster tools. Raster extraction становится fallback для обычного рисунка, semantic hit testing — для objects.

**Gate:** текст сохраняет строку/стиль и редактируется после reload; copy независим, история восстанавливает doc и объекты, старые PNG выглядят идентично, новые compositing rules не скрывают нарисованные штрихи.

### P2 — persistence и организация кода

1. Новый versioned IndexedDB adapter с transaction document+assets, coalesced save queue и status. Сначала сохранить текущий committed проект; не переносить неограниченную JSON историю автоматически.
2. Миграция v1: брать `history[historyIndex]`, сохранить **все его frames** как raster assets, currentFrame clamp→ID, recent/favorite colors. Если нужен reload Undo — отдельно переносить ограниченный хвост, дедуплицируя assets. Не пропускать corrupted кадры молча: recovery с явным выбором.
3. Старую запись не удалять, пока новая transaction не завершилась и новый документ не прочитан/проверен. Migration marker ставить вместе с commit. При failed migration использовать старый проект/recovery без перезаписи. Откат на v1 не должен читать stale legacy вместо нового документа: предусмотреть экспорт/legacy compatibility snapshot либо явный запрет такого downgrade без восстановления.
4. Разделить domain reducer, pending/interaction, renderer, import, storage по указанным границам; сохранить existing UI components. Постепенно усиливать type contracts и убрать дублирующие callbacks/textInput state только после тестов.

**Gate:** reload после successful save точно восстанавливает последнюю revision; quota/error/закрытие вкладки не дают видимого ложного «сохранено»; source v1 сохранён до верификации, orphan assets не удаляются из history/pending.

### P3 — performance, UX, accessibility

1. Mobile layout, canvas fit, text input scale/keyboard/fonts, ограничение touch-action drawing surfaces; доступный frame select/delete/reorder/FPS и modal focus management.
2. rAF batching previews, bounded playback decode cache. Оптимизировать длинные strokes/extraction/fill по измерениям; сравнить pixel output.
3. GIF progress/cancel; worker encoding если long tasks подтверждены. Уменьшить лишние decode/base64 copies и определить resource limits для импорта/экспорта.
4. Недеструктивная, последовательная moderation policy, alpha-aware detectors, downsample/bounded line comparisons, корпус false-positive fixtures.
5. Небольшой logo asset, отдельный Git cleanup tracked node_modules/.vs, переносимый clean script, CI с typecheck+tests+build. Не смешивать housekeeping и data model migration в одном diff.

**Gate:** проверены portrait/landscape/virtual keyboard и keyboard navigation; UI остаётся отзывчивым на согласованных stress fixtures; экспорт/рисунок/undo не изменились от оптимизаций.

## Tests required before refactoring

Сейчас покрыты только безопасный цветной patch, чёрно-красный X и mock PNG anchor. Новый test runner/браузерные зависимости в рамках этого аудита не устанавливались. Простые pure tests можно позже продолжить писать через существующий `tsx`; настоящее React/Canvas поведение требует отдельного browser integration слоя, а не только самодельных mock hooks.

### Минимальный блок до P0

1. **Selection transaction:** отдельный объект → connected extract → move → finalize → Undo возвращает исходные пиксели без дырки/дубликата → Redo возвращает новую позицию. Тот же сценарий rect select, no movement, scale, flip, tint, delete, cancel, blank click. Проверять committed bitmap, overlay, frames, history count и reload/export, а не только screenshot.
2. **Pending × transitions:** selection/text/sticker × switch/add/copy/delete/reorder/Undo/Redo/clear/import/play/export. На исходном кадре выбранная policy выполнена ровно один раз; на соседнем нет чужого объекта; после операции нет stale flags. Особо selection → switch → finalize и activeText Enter во время playback.
3. **History/navigation:** A→B→C→Undo→D исключает C; no-op не пишет state; два commits в одном React event не теряются; Undo добавления 2-го/3-го кадра, Undo удаления и reorder не оставляют invalid selected frame. New stroke после Undo не создаёт holes. Limit 50 и загрузка истории >50; Ctrl+Shift+Z без redo ничего не отменяет; input shortcuts не перехватываются.
4. **Async loading/import:** callbacks decode завершаются в обратном порядке; во время загрузки switch/Undo/добавление/новый stroke/удаление цели/второй import. Новые revisions сохраняются. Reader error, abort, invalid image, decode failure, очень большое encoded/decoded изображение. Import не очищает кадр до успешного decode.
5. **Pointer lifecycle в реальном браузере:** down/move/up внутри и снаружи, cancel кисти/ластика/selection/sticker, lost capture, второй pointer, pen, touch и правый/middle mouse. Проверить refs, preview, историю и отсутствие «продолжающегося» resize после cancel. CSS scale 0.5/1/1.5, изменение viewport и выход за край.
6. **Persistence:** valid v1, malformed JSON, empty history, invalid indices, invalid frame string, holes/null, oversized data, read denied. Full write success; quota first failure/fallback success сохраняет все frames; обе записи failed показывают статус и не теряют предыдущие данные. Playback не пишет весь проект на tick; palette не сериализует raster history без необходимости.
7. **Moderation data safety:** чёрный+красный квадраты, синий X, обычный плюс, цветная заливка, симметричный орнамент, фото и прозрачное RGB-содержимое. Предупреждение не уничтожает работу. Все требуемые commit/import/export пути имеют согласованную policy; cooldown влияет на уведомление, а не пропускает analysis. Отдельно history behavior при отказе candidate.
8. **Export:** PNG соответствует видимому committed результату после resolver; GIF frame count/order/delay/dimensions/white-alpha policy, decode error одного кадра, null context/encoder failure снимают busy. Реальное скачивание Blob и timing revoke проверяются браузером. Pending и failed selected frame не дают undefined URL.

### Перед P1/P2

9. **Text ownership:** два кадра с пересекающимися coordinates и разными строками; copy независим, Undo/Redo edit, clear/delete/reorder, растровое перемещение старого текста. После reload текстовый объект имеет исходные font/size/color/строку; старый PNG не превращается в выдуманный текст. Набор кириллицы/emoji/разной ширины glyphs; IME Enter и multiline policy.
10. **Hybrid renderer:** raster + objects с overlap, object hit testing, flatten before erase/fill/brush, Undo flatten, clipping за краями, transparent image, белые части sticker. PNG/GIF/main Canvas дают один composite без selection borders/template.
11. **Migration:** v1 undone position берётся по historyIndex; все frames и цвета переносятся; repeated migration идемпотентна. IDB transaction rollback/error/quota, закрытие до/после commit, проверка чтения v2, recovery corrupted assets, ограниченный history tail, asset GC не удаляет undo/redo/pending/export resources. Старая запись остаётся до gate.

### Перед P3 и при релизе

12. **UI/device:** viewport 320×568, 375×667, 390×844, 667×375, 844×390, tablet и desktop; virtual keyboard, rotation и browser zoom. Rect/input metrics проверяются относительно реального displayed canvas, не viewport; font load delayed/offline. Timeline scroll/reorder/FPS и panel доступность на touch.
13. **Accessibility:** keyboard selection/reorder/delete frames и objects, modal focus trap/Escape/restore, names/states для buttons/inputs, warning/save status, reduced motion. Canvas drawing остаётся pointer-driven, но управление документом доступно клавиатурой.
14. **Performance measurements:** sparse drawing, dense fill, imported photo, long 10k-point stroke, 20/100 frames; peak memory, serialized/blob bytes, commit/autosave/GIF latency, longest task и input responsiveness. Dense moderator fixture — отдельный bounded stress test, чтобы O(L²) не подвесил CI. Бюджеты устанавливать по baseline устройств, не по произвольным обещаниям FPS.
15. **Release smoke:** typecheck, tests, production build; реальные brush/fill/shapes/text/stickers, reload, animation и download PNG/GIF. Build success сам по себе не проверяет interaction.

## Risks

- **Самая опасная граница — bitmap / pending / history.** Частичный фикс snapshot без единого commit оставит silent data loss на navigation/export/reload. Сначала контракт, затем перенос кода.
- **React batching и mutable Canvas.** DOM mutations выполняются немедленно, setters — по render циклам; перенос callbacks без атомарной модели может поменять порядок. Mock setters дают полезную демонстрацию, но нужны integration tests в StrictMode.
- **Асинхронное декодирование и переключение кадров.** Image callbacks должны быть актуальны и не менять document; import должен знать цель и revision. Playback cache тоже требует ownership/disposal.
- **Compositing гибридной модели.** Raster base + upper objects меняет перекрытие старых инструментов. Flatten должен быть undoable и ожидаемым; иначе новая «редактируемость» ухудшит само рисование.
- **Миграция storage.** JSON history раздута, старые строки могут быть invalid, transient extraction snapshots уже могли попасть в сохранения. Нельзя автоматически угадать потерянный объект/текст; нужен recovery, исходный storage и экспорт перед разрушительными действиями.
- **Asset GC и history budget.** Удаление ресурса, доступного Undo/Redo/pending/export, сломает восстановление. Reference reachability важнее самого факта удаления кадра.
- **Модерация.** Текущие tests закрепляют один blocked fixture, но не защищают обычные рисунки. Изменение threshold без изменения destructive policy не устраняет главный риск. Требования «запретить навсегда» и «Undo всё восстанавливает» должны иметь явную продуктовую границу.
- **Fonts/emoji/alpha.** Браузеры/ОС и загрузка webfonts меняют metrics и emoji rendering. Старый flattened PNG визуально стабилен; новые semantic objects требуют общего renderer/font policy и экспортных fixtures.
- **Pointer/resize/mobile.** Capture не означает корректный multi-pointer lifecycle. Scale, virtual keyboard, global touch-action и высота timeline проверяются на настоящем браузере; одного desktop click-test недостаточно.
- **Оптимизация алгоритмов.** Incremental smoothing, gap-closing fill и extraction masks могут поменять пиксельный результат. Сначала эталонные изображения, затем замеры, затем изменения.
- **Слишком крупный рефакторинг.** Одновременная замена history, storage, renderer и layout делает причины регрессий неразличимыми. Gate каждого этапа обязателен; каждый этап должен оставлять рабочий редактор и путь чтения предыдущих данных.

Рекомендуемый порядок: characterization tests → P0 data safety → P1 IDs/transactions/history/text objects → P2 versioned IndexedDB и разделение модулей → P3 mobile/accessibility/performance. IndexedDB улучшает сохранение, но сам по себе не исправляет исчезновение объектов, чужой pending или гонки импорта.
